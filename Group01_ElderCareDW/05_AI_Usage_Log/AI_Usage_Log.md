  ให้ตรงกับโค้ด เพราะ M2 ถ่วงน้ำหนัก M1/M3/M4 และเป็นตัวหารของ M9
- **ไม่รับ:** _(เติมเมื่อพิจารณาแล้ว)_

### ตรวจสอบความถูกต้องอย่างไร

รัน `python verify_facts.py` — **ผ่าน 21 ข้อ ตก 0 ข้อ** ข้อที่มีน้ำหนักที่สุดคือ
**การกระทบยอดกับตัวเลขที่ CMS คำนวณมาเอง** ซึ่งเป็นการตรวจที่ไปป์ไลน์เราไม่มีทางทำให้ผ่านเองได้

| ตรวจอะไร | วิธี | ผล |
|---|---|---|
| ยอดค่าปรับรายสถานที่ | จำกัด Fact 2 ให้เหลือเฉพาะรายการที่อยู่ในแฟ้ม Penalties งวด มิ.ย. 2569 แล้วเทียบกับคอลัมน์ `Total Amount of Fines in Dollars` ใน ProviderInfo | **ตรงกันครบ 6,563 แห่ง ยอดรวม $459,054,863 เท่ากันถึงหลักดอลลาร์** |
| Grain ของ Fact 1 | `GROUP BY snapshot_date_key, ccn HAVING COUNT(*) > 1` | 0 แถว และเหลือ 3 งวดตามที่ควรเป็น (งวดเผยแพร่ซ้ำถูกยุบ) |
| คีย์นอกครบทุกเส้น | `LEFT JOIN` กับทุก dimension แล้วนับแถวที่ไม่เจอคู่ | 0 orphan ทั้ง 8 เส้น |
| `chain_key = Unknown` มาจากไหน | นับแยกตามปีของงวด | 15,578 แถว เป็นของงวด 2562 **ล้วน** ตรงกับที่ยุคนั้นไม่มีคอลัมน์เครือ |
| ค่าปรับกับการระงับการจ่ายเงินไม่ปนกัน | `SUM(fine_amount_usd)` แยกตามประเภท | Payment Denial ได้ **$0** ครบ 4,160 รายการ |
| แถวทดสอบ CCN 015009 งวด มิ.ย. 2569 | อ่านจาก Fact 1 | 52.4 / 57 = **91.93%** และ `resident_days` = 1,572 = 52.4 × 30 วัน |

**ผลการตรวจ: ข้อกระทบยอด "ตก" ในการรันครั้งแรก** — ยอดของเราสูงกว่า CMS อยู่ $14.3M
ใน 232 แห่ง ไล่หาสาเหตุจนพบว่า **คำถามตรวจเขียนผิด ไม่ใช่ไปป์ไลน์ผิด**

ตัวอย่างที่ใช้ไล่: CCN `035062` เราได้ $100,018 แต่ CMS บอก $77,018 ส่วนต่าง $23,000
คือ Fine ID `139504` วันที่ 2026-04-15 ซึ่ง **มีเฉพาะในแฟ้มเดือน ก.ค. ไม่มีในแฟ้มเดือน มิ.ย.**
เพราะถูกรายงานทีหลัง เทียบชุด Fine ID ทั้งสองแฟ้มแล้วได้ภาพชัด: มีในเดือน ก.ค.
แต่ไม่มีในเดือน มิ.ย. **454 รายการ** และมีในเดือน มิ.ย. แต่ไม่มีในเดือน ก.ค. **477 รายการ**
(หลุดออกจากหน้าต่าง 3 ปีไปแล้ว)

แปลว่าคลังข้อมูลของเรามีค่าปรับ **393 รายการ มูลค่า $19.6M ที่ไม่มีในแฟ้มงวดใดงวดเดียว**
ซึ่งคือคุณค่าของ Fact 2 ที่เอกสารออกแบบอ้างไว้พอดี พอแก้คำถามตรวจจากการกรอง
"ช่วงวันที่" เป็นการกรอง "ชุดรายการที่แฟ้มนั้นมีจริง" ยอดก็ตรงกันครบทุกแห่ง
