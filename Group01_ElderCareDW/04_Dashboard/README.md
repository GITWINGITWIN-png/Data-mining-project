## ตรงตามเกณฑ์ของโจทย์อย่างไร

`verify_dashboard.py` **นับจากโค้ดจริง ไม่ใช่เขียนอ้างไว้เฉย ๆ**

| เกณฑ์ | ต้องมี | มีจริง |
|---|---|---|
| Measures สรุป Business Performance | ≥ 3 | **10** (M1 M3 M4 M5 M7 + จำนวนสถานที่ ในแถบบนและแท็บ BQ6) |
| กราฟ | ≥ 5 | **13** |
| การวิเคราะห์ตามช่วงเวลา | ≥ 1 | **2** — BQ5 แนวโน้มรายงวด · BQ7 ค่าปรับรายปี 2559–2569 |
| การเปรียบเทียบข้อมูล | ≥ 1 | **2** — BQ2 รูปแบบการถือครอง · BQ8 ขนาดเครือ |
| Filter / Interactive Control | ≥ 2 | **5** — งวด · รัฐ · การถือครอง · ขนาดเครือ · สวิตช์แถวน่าสงสัย |
| Insight และข้อเสนอแนะ | ≥ 5 | **8** (ข้อละหนึ่ง BQ) |

ทุกกราฟผูกกับคำถามทางธุรกิจที่ประกาศไว้ในเอกสารออกแบบ และ `verify_dashboard.py`
ตรวจว่า BQ1–BQ8 มีทั้งแท็บและ Insight ครบทุกข้อ

## หลักที่ยึดในโฟลเดอร์นี้

### 1. อ่านจากวิว ไม่แตะตาราง Fact

`03_Data_Warehouse/views.sql` นิยาม M1–M10 ไว้แล้วที่เดียว แดชบอร์ดที่ข้ามวิว
ไปเขียน `AVG(residents/beds)` เองจะได้อัตราการเข้าพักสูงเกินจริงราว 1.7 จุด **โดยไม่มี error**
แท็บ "คุณภาพข้อมูล" มีกราฟเทียบสองวิธีนี้ไว้ให้เห็นด้วยตา

### 2. สูตร measure ซ้ำได้ แต่ต้องมีตัวจับ

ตัวกรองทำให้ใช้วิวที่รวมยอดไว้ล่วงหน้าไม่ได้ (`v_measure_by_state_period` จัดกลุ่มตามรัฐไปแล้ว
จึงตอบ "เฉพาะ 4 รัฐนี้ เฉพาะ Non profit" ไม่ได้) แดชบอร์ดจึงต้องรวมยอดเอง
สูตรจึงอยู่สองที่คือ `queries.MEASURES_SQL` กับ `views.sql`

**ความซ้ำนี้ถูกจับด้วยเทสต์ ไม่ใช่ด้วยความไว้ใจ** — `verify_dashboard.py` คำนวณทุก measure
ผ่านค่าคงที่ในแดชบอร์ดแล้วเทียบกับวิวในคลังที่ระดับ 1e-9 ถ้าใครแก้ที่หนึ่งแล้วลืมอีกที่ เทสต์จะตก

### 3. Insight คำนวณสด ไม่ใช่ข้อความตายตัว

Insight ที่ hard-code ไว้คือข้อความที่ **เคย** จริงกับข้อมูลชุดหนึ่ง และไม่มีอะไรทำให้มันเปลี่ยนตาม
กราฟข้างบนเมื่อข้อมูลเปลี่ยน ที่นี่ข้อความกับกราฟอ่านตัวเลขชุดเดียวกันในคำขอเดียวกัน
จึงขัดกันเองไม่ได้ และการขยับตัวกรองจะคำนวณข้อสรุปใหม่ทั้งหมด

แต่ละข้อมีป้ายบอกน้ำหนักหลักฐาน — 🟢 หนักแน่น · 🟡 ยังบาง · 🔴 ยังตอบไม่ได้
พร้อมช่อง "ข้อควรระวัง" ที่เขียนข้อจำกัดไว้ตรง ๆ เช่น BQ5 ที่มีแค่ 3 จุดเวลา
หรือ BQ1 ที่ยังขาดข้อมูลประชากร

### 4. แสดงสิ่งที่ยังไม่มี ไม่ใช่ซ่อน

แท็บ "คุณภาพข้อมูล" และคำเตือนสีเหลืองตามแท็บต่าง ๆ บอกตรง ๆ ว่า

- **BQ5 ยังไม่ใช่อนุกรมเวลา** มีแค่ 3 จุด และสองจุดแรกห่างกัน 7 ปี
- **ช่องว่างปี 2562–2565 ในกราฟค่าปรับ ไม่ใช่ปีที่ไม่มีการลงโทษ** แต่เป็นผลของหน้าต่างหมุน 3 ปี
  ของแฟ้ม CMS — คลังเห็นเฉพาะช่วงที่งวดซึ่งโหลดไว้ครอบคลุมถึง
- **M10 กับ BQ1 ยังตอบไม่ได้** เพราะ `pop_65plus` ว่างทั้งคอลัมน์
- **แฟ้ม Penalties ของงวด 2026-07-29 ถูกทิ้งทั้งแฟ้ม** ตัวเลขค่าปรับทุกตัวจะเปลี่ยนเมื่อแก้บั๊กนั้น

## บทเรียนจากการตรวจ — บั๊กสองข้อที่เทสต์ปกติจับไม่ได้

**1. Streamlit ไม่นับพารามิเตอร์ที่ขึ้นต้นด้วย `_` เข้าไปในคีย์ของแคช**
ตอนแรกเขียนว่า `def cached(_fn_name, _con, ...)` ผลคือทุกการเรียกที่ใช้ตัวกรองเดียวกัน
**ชนคีย์กันหมด** — `trend()` ได้ผลลัพธ์ของ `kpis()` กลับมา และเป็นความผิดพลาดแบบเงียบ
คือรูปร่างข้อมูลผิดไปโผล่ที่กราฟ ไม่ใช่ error ตรงจุดที่เรียก
จับได้ด้วยการรัน `python app.py` ตรง ๆ (bare mode) ไม่ใช่ด้วยการอ่านโค้ด

**2. `market()` พังเมื่อกรองรัฐ** เพราะ join `v_market_saturation` เข้ามาแล้วทำให้ชื่อคอลัมน์
`state_code` กำกวม — เทสต์ที่ไม่ใส่ตัวกรองจะไม่มีวันไปถึงบรรทัดนั้น
ตอนนี้ `verify_dashboard.py` มีชุดตรวจ "ตัวกรองแบบกวน ๆ" 6 แบบ รวมถึงแบบที่กรองแล้วไม่เหลือข้อมูลเลย

## ภาพประกอบสำหรับรายงาน

โจทย์กำหนดให้รายงานมี *"ภาพ Dashboard ที่สมบูรณ์และตัวอย่างการใช้ Filter"*
และภาพต้องอ่านชื่อกราฟ แกน ตัวเลข และคำอธิบายได้ชัด แนะนำให้จับภาพอย่างน้อย

1. หน้าเต็มพร้อมแถบตัวเลขสรุป (ยังไม่กรอง)
2. หน้าเดียวกันหลังกรองรัฐ 3–4 รัฐ — ให้เห็นว่าตัวเลขและกราฟเปลี่ยนตาม
3. แท็บ Insight ที่กางข้อความออก
4. แท็บคุณภาพข้อมูล ตรงกราฟเทียบ SUM/SUM กับ AVG ของอัตราส่วน
