## ทำไมแยกเป็นสามชั้น

| ไฟล์ | หน้าที่ | กฎ |
|---|---|---|
| `queries.py` | คำนวณ **ทุก** ตัวเลข | ไม่มีการวาดกราฟ |
| `charts.py` | รับ DataFrame คืน Figure | ไม่มีการ query และไม่คำนวณตัวเลข |
| `app.py` | จัดหน้าจอและตัวกรอง | ไม่คำนวณอะไรเลย เรียก `queries.py` อย่างเดียว |

เหตุผลคือ **โน้ตบุ๊ก เอกสารคำตอบ และแดชบอร์ด ต้องให้ตัวเลขตรงกันโดยโครงสร้าง ไม่ใช่โดยบังเอิญ**
ตัวเลขที่ตรวจแล้วในเซลล์โน้ตบุ๊กคือการเรียกฟังก์ชันตัวเดียวกันกับที่แดชบอร์ดเรียก
ถ้าใครแก้สูตรที่ `queries.py` ทั้งสามที่จะเปลี่ยนพร้อมกัน — ไม่มีทางที่กราฟกับตารางข้าง ๆ
จะขัดกันเองได้

## กฎการรวมค่าที่บังคับไว้ใน `queries.py`

ไม่ปล่อยให้คนเขียนกราฟคนถัดไปตัดสินใจเอง เพราะนี่คือจุดที่งานคลังข้อมูลพลาดบ่อยที่สุด

- **อัตราส่วนคือผลรวมหารผลรวม** — `SUM(ผู้พักอาศัย) / SUM(เตียง)` ไม่ใช่ค่าเฉลี่ยของอัตราส่วนรายแห่ง
  (บ้าน 20 เตียงกับ 300 เตียงจะมีน้ำหนักเท่ากันทันทีถ้าทำผิด)
- **HPRD และอัตราลาออกถ่วงน้ำหนักด้วยจำนวนผู้พักอาศัย** เพราะเป็นอัตราต่อหัวอยู่แล้ว
  และคืนค่าไม่ถ่วงน้ำหนักมาคู่กันเสมอ (`*_unweighted`) เพื่อให้เห็นช่องว่าง ไม่ใช่ซ่อนไว้
- **คะแนนดาวเฉลี่ยเฉพาะแห่งที่ CMS ให้คะแนน** — นับบ้านเปิดใหม่ที่ยังไม่มีคะแนนเป็น 0
  จะทำให้รัฐที่มีการก่อสร้างมากดูแย่ลงโดยไม่มีเหตุผล
- **ค่าปรับต้องรวมให้เหลือระดับ CCN ก่อนเชื่อมกับ Fact 1 เสมอ** — Fact 1 มีหนึ่งแถวต่อ
  สถานพยาบาลต่องวด ส่วน Fact 2 มีหนึ่งแถวต่อค่าปรับ การ `JOIN` ตรง ๆ จะทำให้เตียงถูกนับซ้ำ
  ตามจำนวนค่าปรับ (วัดจริงแล้วพองขึ้น **2.1 เท่า**) `facility_roster()` จึงบังคับลำดับนี้ไว้
  ให้เขียนผิดไม่ได้

## หมายเหตุที่ควรรู้ก่อนแก้โค้ด

- **`st.stop()` ห้ามใช้ในตัวแท็บ** มันหยุดทั้งสคริปต์ แท็บที่เหลือจะว่างหมด
  ถ้าต้องข้ามส่วนที่ไม่มีข้อมูล ให้ใช้ `if/else` ครอบเฉพาะส่วนนั้น
- **ตัวกรองส่งเป็น tuple** เพราะ `st.cache_data` ต้อง hash อาร์กิวเมนต์ได้
  แล้วแปลงกลับเป็น list ที่จุดเรียก
- **งวดปี 2562 ไม่มีคอลัมน์อัตราลาออกและคอลัมน์เครือ** โค้ดทุกจุดที่ใช้สองคอลัมน์นี้
  ต้องรับมือกับกรณีที่ไม่มีข้อมูลเลย — `test_dashboard.py` มีเคสนี้อยู่ 3 เคส
