# บันทึกการใช้งาน AI โครงงาน ElderCare Insight (สรุป Prompt สำคัญ)

เอกสารฉบับนี้สรุปรายการการใช้งาน AI ที่สำคัญสำหรับการสร้าง Data Warehouse และ Dashboard ตามข้อกำหนดของโครงงานที่ระบุให้มีสรุปการใช้งาน AI อย่างน้อย 5 Prompt พร้อมระบุคำแนะนำของ AI, การนำไปใช้/แก้ไข, และวิธีตรวจสอบความถูกต้อง [cite: 2] 

## 1. การตรวจสอบเอกสารออกแบบและโครงสร้าง (12 ส.ค. 2569)
> [!quote] Prompt
> *"Could you review the repository here? You could see the detail requirements in 69-1-Mini DW & Dashboard-1.pdf..."* [cite: 1]

- **สิ่งที่ AI แนะนำ:** ชี้จุดที่ต้องแก้ไขในโครงสร้างไฟล์ เช่น ไฟล์ `.gitkeep` ที่มีพาร์ทของเครื่องอื่นติดมา [cite: 1] และให้ข้อสังเกตด้านการออกแบบ Data Warehouse 6 ข้อ เช่น การเก็บตัวคูณ VBP ที่อาจทำให้เกิดการนับซ้ำ หรือ Primary Key ของตาราง Fact ที่อาจมีปัญหา [cite: 1]
- **การนำไปใช้:** กลุ่มได้ปรับโครงสร้างโฟลเดอร์ตามคำแนะนำทันที [cite: 1] ส่วนข้อสังเกตด้าน Data Warehouse นั้น เก็บไว้เพื่อพิสูจน์ด้วยข้อมูลจริงในภายหลัง [cite: 1]
- **การตรวจสอบ:** ตรวจสอบโครงสร้างไฟล์ในเครื่องว่าตรงกับที่ต้องการแก้ไขจริง [cite: 1]

## 2. การสร้าง ETL สำหรับ Dimension และ Fact Tables (12 ส.ค. 2569)
> [!quote] Prompt
> *"ทำ ETL ของ ตารางDIM 6 ตาราง"* และตามด้วย *"ทำ ETL ของ FACT"* [cite: 1]

- **สิ่งที่ AI แนะนำ:** เสนอให้จัดโครงสร้างไฟล์ ETL แยกตามขั้นตอน และเสนอทางเลือกเชิงออกแบบ เช่น การเพิ่มแถว `key = -1` สำหรับค่า "ไม่ทราบ" และการเทียบ SCD2 เฉพาะคอลัมน์ที่ทราบค่า [cite: 1] สำหรับตาราง Fact เสนอให้ยุบข้อมูลจากงวดที่เผยแพร่ซ้ำ [cite: 1]
- **การนำไปใช้:** นำโครงสร้างมาใช้ แต่ได้ปรับแก้โดยให้ทำตัวพิมพ์ใหญ่ก่อนที่จะเทียบ SCD2 เพื่อป้องกันการนับซ้ำของชื่อสถานที่ [cite: 1] สำหรับ M2 ตัดสินใจรอข้อสรุปของกลุ่มก่อนแก้เอกสาร [cite: 1]
- **การตรวจสอบ:** เขียนสคริปต์ `verify_dims.py` และ `verify_facts.py` ขึ้นมาสอบถามผลลัพธ์ผ่าน SQL แยกต่างหากจากโค้ดที่สร้าง ซึ่งผ่านข้อทดสอบ 22 ข้อ [cite: 1]

## 3. การตรวจสอบและแก้ไขบั๊กในระบบ ETL (12 ส.ค. 2569)
> [!quote] Prompt
> *"ตรวจสอบความถูกต้องของ ETL ที่เพิ่มมา"* และตามด้วย *"recheck etl error trougly and inform me is dedup is only error"* [cite: 1]

- **สิ่งที่ AI แนะนำ:** หลังจากให้ AI รันข้อมูล 4 งวด พบข้อผิดพลาดร้ายแรง เช่น `Fact_Penalty_Event` มีการนับยอดซ้ำไปกว่า $382 ล้าน [cite: 1] และบั๊กที่ชื่อเมืองเดียวกันแตกเป็นหลายคีย์เนื่องจากการใช้ตัวพิมพ์เล็ก/ใหญ่ต่างกัน [cite: 1]
- **การนำไปใช้:** นำวิธีแก้ปัญหามาปรับใช้ทั้งหมด เช่น ใช้คีย์ธรรมชาติควบคู่กับ `occurrence` ในการระบุตัวตนทุกยุค และสร้างฟังก์ชันกลางเพื่อให้ Fact และ Dimension ใช้กฎ Normalize ตัวพิมพ์เดียวกัน [cite: 1]
- **การตรวจสอบ:** ตรวจสอบด้วย Query อิสระเพื่อดูว่าค่าปรับใบเดียวกันได้คีย์ซ้ำหรือไม่ และใช้ `fk_check` ตรวจว่าการ Join ระหว่างตารางเกิดปัญหา orphans หรือไม่ [cite: 1]

## 4. การออกแบบ Schema และข้อบังคับคลังข้อมูล (13 ส.ค. 2569)
> [!quote] Prompt
> *"Fix the smaller points, and then design Datawarehouse in /03_Data_Warehouse"* [cite: 1]

- **สิ่งที่ AI แนะนำ:** สร้างไฟล์ `schema.sql` และ `views.sql` เพื่อเพิ่มชั้นข้อบังคับ (Constraints) เช่น PK/FK และ CHECK ป้องกันข้อมูลผิดปกติเข้าสู่ระบบ [cite: 1] 
- **การนำไปใช้:** นำโครงสร้าง Schema และ Views ไปใช้ แต่แก้ไขเรื่องเงื่อนไขของรหัสไปรษณีย์ที่ความยาว 7 ตัวเมื่อเป็น 'Unknown' และเปลี่ยนคำสั่งจากการ Rename ตารางเป็นการ Copy แล้ว Drop แทนเมื่อทำงานซ้ำ [cite: 1]
- **การตรวจสอบ:** ทดสอบยิงข้อมูลที่ตั้งใจทำให้ผิดเงื่อนไข (เช่น บังคับอัปเดต Rating = 9) เข้าฐานข้อมูล เพื่อพิสูจน์ว่าระบบ Constraint สามารถปฏิเสธข้อมูลที่ผิดได้จริง [cite: 1]

## 5. การสร้าง Interactive Dashboard (13 และ 22 ส.ค. 2569)
> [!quote] Prompt
> *"Could you design dashboard interactive dashboard that satisfies the requirement..."* และ *"ตรวจสอบผลการคำนวนคำถามทั้ง 8 ข้อ... จากนั้นนำไปสร้าง dashboard ให้ได้ตามข้อกำหนด"* [cite: 1]

- **สิ่งที่ AI แนะนำ:** ออกแบบโครงสร้าง Dashboard บน Streamlit (app.py, queries.py, insights.py) [cite: 1] นอกจากนี้ยังเตือนถึง "ปัญหาความเป็นวงกลม" ในข้อ BQ3 โดยแนะนำให้ใช้คะแนนการตรวจสุขภาพแทนคะแนนดาวรวม เพื่อไม่ให้ตัวแปรทับซ้อนกัน [cite: 1]
- **การนำไปใช้:** รับโครงสร้างไฟล์ แต่ปฏิเสธการดึงข้อมูลจากตาราง Fact โดยตรง เปลี่ยนไปเรียกผ่าน View ที่เตรียมไว้เพื่อไม่ให้นิยามสูตรซ้ำซ้อน [cite: 1] และแก้ไขข้อความ Insight ให้คำนวณสดจากตัวกรอง แทนที่จะใช้ข้อความตายตัว [cite: 1]
- **การตรวจสอบ:** ทดสอบ Dashboard ด้วยชุดตัวกรองจริง 11 รูปแบบ [cite: 1] และตรวจสอบรูปภาพ Screenshots ด้วย `make_screenshots.py` ที่บังคับว่าตัวเลขรวมจะต้องขยับตามเมื่อถูกตั้งตัวกรองจริง [cite: 1]

## 6. การจัดทำรายงานโครงงานด้วย LaTeX (22 ส.ค. 2569)
> [!quote] Prompt
> *"Make PDF Report contain requiment from @69-1-Mini DW & Dashboard-1.pdf Use LaTex"* [cite: 1]

- **สิ่งที่ AI แนะนำ:** เสนอให้เขียนไฟล์ใหม่แทนการย่อไฟล์เก่า พร้อมเสนอโครงรายงาน 11 หัวข้อตามข้อกำหนด และแนะนำให้เปลี่ยนไปเขียนเป็นภาษาอังกฤษเนื่องจากระบบไม่มีฟอนต์ภาษาไทย [cite: 1]
- **การนำไปใช้:** กลุ่มเลือกเขียนด้วยภาษาอังกฤษเพื่อเลี่ยงปัญหาฟอนต์ และเปลี่ยนไปใช้ฟอนต์มาตรฐานของ TeX แทน [cite: 1] ส่วนหน้าปก มีการแก้ไขปรับรูปแบบเองให้ดูเป็นทางการมากขึ้นตามภาพตัวอย่าง [cite: 1]
- **การตรวจสอบ:** เช็คไฟล์ `.log` ว่าไม่มี error หรืออักขระที่ฟอนต์ไม่มี ตรวจสอบว่าความยาวของเนื้อหาผ่านเกณฑ์ (ได้มา 15 หน้า) [cite: 1] และตรวจสอบภาพหน้าจอว่าชัดเจน สามารถอ่านตัวเลขและแกนกราฟได้ตามโจทย์ [cite: 1, 2]
