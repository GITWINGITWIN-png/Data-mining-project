# 05_AI_Usage_Log — บันทึกการใช้ Generative AI

## ทำไมต้องมีโฟลเดอร์นี้

โจทย์ (หัวข้อ *การใช้ Generative AI*) อนุญาตให้ใช้ AI ช่วยวิเคราะห์ requirement
ออกแบบ data model เขียนโค้ด แก้ปัญหาข้อมูล ออกแบบแดชบอร์ด และอธิบาย insight
**แต่บังคับให้ส่ง AI Usage Log** ซึ่งต้องประกอบด้วย

1. Prompt สำคัญ **อย่างน้อย 5 prompt**
2. สิ่งที่ AI แนะนำ
3. สิ่งที่กลุ่มนำไปใช้หรือแก้ไข
4. **วิธีตรวจสอบว่าผลลัพธ์จาก AI ถูกต้อง**

และระบุชัดว่า *"สมาชิกทุกคนต้องสามารถอธิบายผลงานได้ ไม่ควรคัดลอกผลลัพธ์จาก AI
โดยไม่มีการตรวจสอบ"* — ข้อ 4 จึงเป็นข้อที่มีน้ำหนักที่สุด ไม่ใช่ข้อ 1

## ไฟล์ในโฟลเดอร์นี้

| ไฟล์ | เนื้อหา |
|---|---|
| `AI_Usage_Log.md` | ตัวบันทึกจริง เรียงตามลำดับเวลา |
| `_entry_template.md` | แม่แบบสำหรับคัดลอกไปสร้างรายการใหม่ |

## วิธีบันทึก

**บันทึกทันทีหลังใช้งาน ไม่ใช่ย้อนเขียนตอนใกล้ส่ง** — ช่องที่เขียนย้อนหลังไม่ได้จริง ๆ
คือช่อง "ตรวจสอบอย่างไร" เพราะถ้าไม่ได้ตรวจตอนนั้น ก็จะไม่มีอะไรให้เขียน

1. คัดลอกเนื้อหาใน `_entry_template.md` ไปต่อท้าย `AI_Usage_Log.md`
2. เติมเลขรายการถัดไป วันที่ และชื่อผู้ใช้งาน
3. วาง prompt **ตามที่พิมพ์จริง** ไม่ต้องขัดเกลา
4. สรุปสิ่งที่ AI ตอบ — เอาเฉพาะใจความ ไม่ต้องแปะทั้งคำตอบ
5. เขียนว่ารับมาเท่าไร แก้อะไร **และทิ้งอะไรเพราะอะไร** (ช่องนี้คือหลักฐานว่าไม่ได้คัดลอกมาดิบ ๆ)
6. เขียนวิธีตรวจสอบให้เป็นรูปธรรม — คำสั่งที่รัน ไฟล์ที่เปิด ตัวเลขที่เทียบ

### สิ่งที่นับว่าเป็น "การตรวจสอบ" จริง

| ตรวจแบบนี้ถึงจะนับ | แบบนี้ไม่นับ |
|---|---|
| รันคำสั่ง/โค้ดแล้วเทียบผลกับค่าที่รู้อยู่แล้ว | "อ่านแล้วดูสมเหตุสมผล" |
| เปิดไฟล์ข้อมูลจริงแล้วนับแถว/คอลัมน์เอง | "AI บอกว่ามั่นใจ" |
| เทียบกับ `NH_Data_Dictionary.pdf` หรือคู่มือ CMS | "ถาม AI ซ้ำแล้วตอบเหมือนเดิม" |
| ให้สมาชิกอีกคนอ่านแล้วอธิบายกลับได้ | "ไม่มี error ตอนรัน" |

### กฎของกลุ่ม

- ทุก **[ตรวจแล้ว]** ในเอกสารออกแบบต้องมีรายการในบันทึกนี้รองรับ ถ้าตัวเลขนั้นมาจาก AI
- ห้ามใส่ **[ตรวจแล้ว]** ให้กับสิ่งที่ AI บอกแต่ยังไม่ได้เปิดข้อมูลจริงดู — ใช้ **[ยังไม่ตรวจ]**
- ก่อนอัดวิดีโอ สมาชิกทุกคนต้องอ่านบันทึกนี้จบ และต้องอธิบายรายการของตัวเองได้โดยไม่เปิดดู
